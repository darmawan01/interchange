# ADR-0036 — Plugin determinism is a test, not a convention

**Status:** Accepted
**Date:** 2026-08-30 · **Phase:** 2

## Context

ADR-0033 puts generated output in the repository behind a regenerate-and-diff gate. That gate
inherits every source of nondeterminism in every generator under it. Go map iteration order is
randomised on purpose; a plugin that ranges over a map of services, or of flags, or of imports, and
emits as it goes produces a different file most runs. protoc's own file ordering is not ours to
depend on either. The result is a `verify` step that fails on branches where nothing changed —
and a gate that flaps is a gate people learn to bypass, at which point committing generated output
has bought nothing and cost a large diff.

"Sort before emitting" as a written convention is not enough, because the failure is intermittent:
a plugin can range over a two-element map and pass for months.

## Decision

Determinism is a property each plugin proves. Every generator sorts before emitting — files by
path, services and methods by name, flags by flag name, transports by enum value, imports by path —
uses no timestamps and no per-build version string in its header, and ships a determinism test that
generates twice over identical input and compares bytes, alongside a golden test that pins the
output itself. `docs/07-codegen.md` states the rules; the tests are what enforce them.

## Consequences

The drift gate is trustworthy, which is the only thing that makes ADR-0033 worth its cost. A
failing `verify` means the contract moved, every time, so nobody learns to re-run CI and hope.

Sorted output also reads better in review: transports come out in enum order rather than the order
someone typed them in the `.proto`, and the emitted list is deduped, because it is a set and
generated bytes must not depend on typing order.

The costs are ordinary but not free. Generated output cannot preserve source order where source
order is meaningful — and where it *is* meaningful the plugins say so explicitly: the DSL emits
fields and enum values in numeric order but keeps declaration order for messages, enums, services
and RPCs. Headers carry no plugin version, so a generated file does not record which build produced
it, and a bug fix in a generator is only visible as the diff it produces. And every new generator
inherits the obligation: a third-party plugin in the same pipeline can flap the gate for everyone,
which is why the rules are documented as rules for plugin *authors* rather than as internal notes.

## Alternatives

**Normalise after generation** — run the whole tree through a formatter or a canonical sorter
before the diff. Rejected: it hides nondeterminism rather than removing it, and it cannot fix
ordering inside a generated list.

**Compare ASTs rather than bytes in `verify`.** Rejected: the committed file is what a human reads,
so byte equality is the property that matters; an AST comparison would let the committed file
shuffle between commits.

**Trust the convention and catch flapping in CI.** Rejected: the signal arrives as an intermittent
red build with no obvious cause, which is precisely the thing that teaches people to ignore the
gate.

## Evidence

- `docs/07-codegen.md` — the five rules for plugin authors:
  guard on `Generate`, `strategy: all`, sort before emitting, fail don't warn, deterministic
  headers (plus the sixth, ADR-0035).
- `tools/cmd/protoc-gen-bus/bus_test.go` — `TestDeterministic`
  generates twice and compares every file; `TestGolden` pins the output against the committed
  package under `tools/testdata/gen`.
- `tools/cmd/protoc-gen-cli/cli_test.go` — `TestDeterministic`
  and `TestGolden`, the same pair.
- `auth/internal/authgen/authgen_test.go` — `TestDeterminism`
  runs the plugin six times and fails if any two runs differ, with the comment that map iteration
  is random and protoc's file order is not ours to depend on, "so this is a real risk rather than a
  formality"; `TestGolden` pins `testdata/permissions.authz.go.golden`.
- `tools/README.md` §"The five rules, as they apply here" —
  what each plugin sorts, and the note that headers carry no timestamp and no plugin version.
- `frontend/dsl/README.md` — the same property for emitted
  `.proto`: "The output is byte-identical for identical input, because it is committed and sits
  under the drift gate", and "Nothing is decoded into a Go map."
- `BUILD-PLAN.md` — cross-phase gate: "Plugins sort before
  emitting — otherwise the drift gate flaps and nobody trusts it."
