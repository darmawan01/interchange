# ADR-0047 — `interchange.yaml` describes a project, not a monorepo of them

**Status:** Accepted
**Date:** 2026-08-30 · **Phase:** 6

## Context

`interchange.yaml` describes one project: one set of proto sources, one generated tree, one
front end, one optional auth policy. `ix generate` reads it, synthesises a `buf.gen.yaml` and runs
buf once. `ix verify` regenerates and fails on a diff. That is the shape the tool is for.

This repository is not that shape. It is a framework monorepo: five proto modules in one buf
workspace — `api`, `auth/api`, `errors/api`, `tools/api` and `examples/catalog/api` — each
generating into its own Go module, with a different managed-mode override and a different plugin
set per module. Making `ix` express that would mean adding a modules array, per-module templates
and per-module outputs to the config, and the only consumer of those features would be the
repository that ships the tool. Bending the tool to its own repository would have been the wrong
lesson to learn from it.

## Decision

The framework generates its own protos from buf templates driven by the Makefile:
`generate-framework` runs `hack/bufgen.sh --template <buf.gen.*.yaml> <module>` once per module.
`examples/catalog` — which *is* the shape `ix` is for — carries the `interchange.yaml` and is
generated by `generate-example`, which runs `ix generate` in that directory. The config file stays
single-project, and the example is what proves it works end to end.

## Consequences

The tool is exercised by a real consumer rather than by its own build. Every finding the example
made against `ix` — per-plugin `include_imports`, `ix doctor` walking up for `buf.yaml`, the rate-
limit retry, `ix verify` double-reporting a stale file — came from using it as an adopter would,
and none of them would have surfaced if `ix` had been pointed at the framework's own tree.

The cost is two generation paths in one repository, and a gate on each. `ix verify` regenerates the
example from `interchange.yaml` and fails on any difference; `make verify` then runs
`git diff --exit-code -- '**/gen/**'` over everything, which is what gates the framework's own five
modules. Both run in CI as one `make verify` step.

The seam between the two paths is not perfectly clean, and it is worth writing down rather than
implying. `generate-framework` also runs `buf.gen.catalog.yaml` over `examples/catalog/api`, so the
example's Go output is produced twice — once by the buf template and once by `ix` — and the two
configurations have to be kept saying the same thing by hand. The TypeScript half is produced only
by the buf template: `buf.gen.catalog.yaml` declares `examples/catalog/node_modules/.bin/
protoc-gen-es` with `include_imports: true`, and `interchange.yaml` declares no TypeScript
generator at all. So `gen/ts` is covered by the `git diff` gate and not by `ix verify`. Nothing
drifts today because both gates run in the same CI step, but a reader should not assume `ix verify`
alone covers the example.

The other cost is honest: a monorepo adopter with several proto modules has no `ix`-shaped answer
yet. They drive buf directly, exactly as this repository does. That is a gap, not a design.

## Alternatives

**Add a modules array to `interchange.yaml`.** Rejected while the only motivating case is this
repository. A config feature with one user, and that user the tool's own build, is a feature
designed against a sample of one.

**Generate everything with `ix` and accept a degraded framework build.** Would have meant either
five `interchange.yaml` files with no top-level command that runs them, or collapsing five modules
into one — which would destroy the layout that enforces the dependency rule (core cannot import the
auth annotation because it lives in a different buf module and a different Go module).

**Generate everything with buf and ship `ix` untested against a real project.** The example is the
only place the whole tool runs as a user runs it. Dropping it would have left `ix generate` and
`ix verify` proven by unit tests over fixtures and by nothing else.

## Evidence

- `Makefile` — `generate: generate-framework generate-example`, and the comment on the target
  states the reasoning; `verify` runs `ix verify` in the example and then `git diff --exit-code --
  '**/gen/**'`.
- `buf.yaml` — the five workspace modules.
- `examples/catalog/interchange.yaml` — one `sources` entry, five generators, one `auth` block.
- `buf.gen.catalog.yaml` — the buf-template half, including the `protoc-gen-es` plugin that
  `interchange.yaml` does not declare.
- `.github/workflows/ci.yaml` — the `verify (drift gate)` step is `make verify`.
- Commit `2f73677` — "The framework's five proto modules generate from buf templates; the example
  — which is the shape ix is actually for — generates through ix."
